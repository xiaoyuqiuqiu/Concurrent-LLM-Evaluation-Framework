📖 自动最佳 QPS 测试方法说明

自动寻优原理

本工具采用迭代倍增并发策略，从并发数 1 开始，每次翻倍（1→2→4→8→16→...→200），自动运行压测并评估 TTFT（首字延迟）和 TPOT（每 Token 生成延迟）是否在用户设定的 SLA 阈值内。当任一指标超过阈值时停止，前一个并发级别即为最优配置。

关键指标定义

指标定义典型 SLA
TTFT (Time To First Token)发送请求到收到第一个 token 的延迟聊天 < 1.5s，实时 < 500ms
TPOT (Time Per Output Token)生成阶段每个 token 的平均耗时流畅阅读 < 50ms，可接受 < 100ms
QPS (Queries Per Second)并发数 ÷ 平均请求延迟(秒)越高越好，但需满足 SLA

测试流程

  1. 选择模型供应商，输入简短的测试提示词（系统使用 max_tokens=32 加速迭代）
  2. 设定 TTFT 和 TPOT 的 SLA 上限（默认 1500ms / 50ms）
  3. 点击"自动寻优"，系统自动倍增并发并记录每轮的 QPS、TTFT、TPOT
  4. 当 TTFT 或 TPOT 超过阈值（或成功率 < 50%）时停止
  5. 查看右侧 4 张图表：QPS 曲线、TTFT 增长、TPOT 变化、成功率趋势
  6. 曲线拐点（TTFT 指数上升、QPS 增长趋缓）即为系统瓶颈所在

结果解读

最佳并发是满足 SLA 的最大并发数。最佳 QPS 是该并发下的实际吞吐量。若最佳并发 = 1，说明单请求就已接近阈值，模型推理速度偏慢或提示词过长。若最佳并发 > 100，说明系统仍有较大余量，可尝试更低的 TPOT 阈值重新测试。
